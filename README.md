
# Genome Assembly Course Project

Genome and transcriptome assembly project for the **Ishikawa** accession of *Arabidopsis thaliana*. The repository contains reproducible shell workflows for read quality control, k-mer analysis, genome and transcriptome assembly, assembly assessment, and comparison with a reference genome.

## Project overview

The biological goal is to investigate the genome of the Ishikawa accession and compare assemblies produced with different assembly strategies. The project also includes transcriptome assembly from a common course RNA-seq accession and evaluates the resulting assemblies using complementary quality metrics.

Computationally, the workflow follows the course sequence:

1. Pre-assembly quality control and read statistics
2. Genome and transcriptome assembly
3. Assembly evaluation
4. Comparison of multiple Arabidopsis assemblies with a reference genome

The reference-based comparison uses MUMmer to align the Flye, Hifiasm, and LJA genome assemblies to the *A. thaliana* TAIR10 reference.

## Dataset

Each student receives a different *A. thaliana* accession or genotype. This project uses **Ishikawa** for the accession-specific genomic data.

- **Genomic data:** PacBio HiFi long reads for the Ishikawa accession.
- **Transcriptomic data:** paired-end RNA-seq reads from the common course accession `RNAseq_Sha`.
- **Additional short-read data:** Illumina paired-end reads are part of the course dataset context and are used where configured by the project workflow.
- **Reference:** *A. thaliana* TAIR10 chromosome-level reference, `Arabidopsis_thaliana.TAIR10.dna.toplevel.fa`.

The setup script links the accession-specific and common transcriptome data into `raw_data/` rather than copying the source files.

- `logs/`: standard output and error logs from submitted jobs.

## Workflow

The numbered scripts are intended to be executed in the following order.

### `00_project_setup.sh`

Defines the accession and transcriptome identifiers, creates the working and log directories, and creates symlinks from `raw_data/` to the course-provided input data.

### `01_run_QC.sh`

Submits FastQC jobs for the Ishikawa genomic reads and the common RNA-seq reads. Reports are written below `read_QC/fastqc/`.

### `02_trim_reads.sh`

Submits fastp jobs for the genomic and paired-end RNA-seq reads. Trimmed reads are stored below `raw_data/trimmed/`, while fastp reports are stored below `read_QC/fastp/`.

### `03_k-mer_counting.sh`

Submits a Jellyfish counting job for the Ishikawa genomic reads and writes the k-mer database to `k-mer_counting/counts/`.

### `04_k-mer_histo.sh`

Uses the Jellyfish count database to generate k-mer histograms in `k-mer_counting/histo/`.

### `05_assembly.sh`

Submits three genome assembly jobs using PacBio HiFi reads:

- Flye, writing to `assemblies/flye/`
- Hifiasm, writing to `assemblies/hifiasm/`
- LJA, writing to `assemblies/LJA/`

It also submits a Trinity transcriptome assembly job using the trimmed paired-end RNA-seq reads, writing to `assemblies/Trinity/`.

### `06_asm_assessement.sh`

Submits BUSCO, QUAST, and Merqury jobs to assess the genome and transcriptome assemblies. Results are organized under `assembly_assessement/busco/`, `assembly_assessement/quast/`, and `assembly_assessement/merqury/`.

### `07_compare_to_reference_with_mummer.sh`

Submits MUMmer jobs that align the Flye, Hifiasm, and LJA assemblies to the TAIR10 reference. The results are written to `assembly_assessement/mummer/`, with separate output prefixes for each assembler.

## Tools used

- **FastQC:** initial read quality control
- **fastp:** read filtering and trimming, with QC reports
- **Jellyfish:** k-mer counting and histogram generation
- **Flye:** PacBio long-read genome assembly
- **Hifiasm:** haplotype-aware HiFi genome assembly
- **LJA:** long-read genome assembly
- **Trinity:** RNA-seq transcriptome assembly
- **BUSCO:** conserved-gene completeness assessment
- **QUAST:** assembly contiguity and statistics
- **Merqury:** k-mer-based assembly quality assessment
- **MUMmer:** whole-genome alignment and reference-based comparison
- **SLURM:** cluster job submission and resource management

## Running the pipeline

Run the driver scripts from the repository root so that their relative paths resolve correctly. The scripts submit jobs with `sbatch`; the SLURM wrappers target the `pibu_el8` partition.

The intended execution order is:

```bash
bash src/00_project_setup.sh
bash src/01_run_QC.sh
bash src/02_trim_reads.sh
bash src/03_k-mer_counting.sh
bash src/04_k-mer_histo.sh
bash src/05_assembly.sh
bash src/06_asm_assessement.sh
bash src/07_compare_to_reference_with_mummer.sh
```

Because the driver scripts submit asynchronous SLURM jobs, check job status and confirm that the expected upstream files are available before starting dependent steps. Cluster paths, module availability, and input locations are configured in the scripts and may need to match the execution environment.

## Outputs

- `read_QC/`: FastQC HTML/ZIP reports and fastp reports for genomic and RNA-seq reads.
- `raw_data/trimmed/`: trimmed genomic and paired-end RNA-seq reads used by downstream steps.
- `k-mer_counting/counts/`: Jellyfish k-mer count databases.
- `k-mer_counting/histo/`: k-mer frequency histograms.
- `assemblies/flye/`, `assemblies/hifiasm/`, and `assemblies/LJA/`: alternative Ishikawa genome assemblies.
- `assemblies/Trinity/`: transcriptome assembly output.
- `assembly_assessement/busco/`: BUSCO completeness results for available assemblies.
- `assembly_assessement/quast/`: QUAST assembly statistics.
- `assembly_assessement/merqury/`: Merqury k-mer-based quality results.
- `assembly_assessement/mummer/`: MUMmer alignment, coordinate, SNP, and plot outputs for each genome assembly compared with TAIR10.
- `logs/out/` and `logs/err/`: SLURM standard output and error logs.

## Reproducibility notes

The repository follows the five workflow organization rules emphasized in the course:

1. **Execute commands from scripts:** driver scripts and SLURM wrappers contain the commands used to run each analysis.
2. **Number scripts by execution order:** the `00_` through `07_` prefixes make the intended sequence explicit.
3. **Use descriptive, active names:** names such as `run_QC`, `trim_reads`, `k-mer_counting`, and `compare_to_reference_with_mummer` state the action and purpose.
4. **Keep scripts specific:** each numbered script covers one workflow stage, while tool-specific execution is isolated in `src/slurm_scripts/`.
5. **Declare directories and variables at the top:** input paths, output paths, accession identifiers, and wrapper locations are defined near the beginning of the driver scripts.

The cluster jobs are submitted through SLURM and record standard output and error logs, supporting traceability of resource use and execution status.
